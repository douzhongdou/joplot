# Joplot 科学图像工作台架构方案

日期：2026-10-01。状态：架构设计，供后续实现与验收使用；本文中的性能目标不是已取得的测试结果。

2026-10-02 更新：二维显示改用视口尺寸的 Canvas，Classic 交互与 Stack 控件已接入主工作台。ITK-Wasm 当前承担 I/O，滤波由 Worker 内的 TypeScript 内核执行。以下仍包含长期目标，实际完成范围以 [实现说明](scientific-image-engine-implementation.md) 为准。

本方案面向浏览器内的科学图像处理：用户需要连续翻阅数百页 Stack，查看原精度像素，并执行滤波、形态学、分割、统计及后续多维计算。工作台采用自有 Dataset 与存储模型管理数据，计算通过 Worker 与 ITK-Wasm 管道接口执行，二维视口从原始数组采样，UI 负责工具、步骤面板和标注。

核心约束是保持数据精度、提前准备原分辨率页面、控制总驻留内存，以及通过操作记录实现撤销。处理步骤不长期保存完整图像或完整 Stack 的 checkpoint。默认科学查看路径不使用低分辨率预览替代原分辨率结果。

## 1 需求与架构决策

| 项目 | 决策 |
| --- | --- |
| 使用场景 | 二维图像编辑与科学分析，连续翻阅数百页；后续扩展三维计算和显示 |
| 计算框架 | ITK-Wasm 为主，按需编译所需算法、数据类型与维度 |
| 显示框架 | 视口尺寸的 Canvas 从原始 TypedArray 最近邻采样；UI 叠加 ROI、标尺、文字和联动标记；后续独立选择三维方案 |
| 数据模型 | 产品自有 Dataset，包含命名轴、像素类型、形状、物理标定和存储引用 |
| 科学精度 | 保留输入精度，不在导入时自动转为 8 位、灰度或浮点低精度表示 |
| 像素显示 | 最近邻取样；禁止默认线性、双三次等混合邻像素的显示插值 |
| Stack 浏览 | 后台解码和计算邻页，使用按字节预算管理的原分辨率缓存 |
| 撤销 | 至少支持撤销最近一次提交的操作；保存步骤及参数，需要时从只读源数据重算 |
| 历史内存 | 不要求保留各步骤完整输出，缓存命中只用于加速，不决定撤销是否可用 |
| 运行位置 | 解码与重计算在 Worker 中执行；React 不执行逐像素计算 |
| 数据位置 | 默认本地处理，不上传用户图像；远程存储与计算属于后续独立扩展 |

不采用 ImageJ1 VirtualStack 的同步翻页读取方式作为默认交互路径。页面尚未准备好时显示明确的加载状态，不能把旧页像素标成新页，也不能显示缩小预览冒充完整结果。

## 2 分层与职责

```text
UI 与工具状态
    │
Dataset 元信息与操作记录
    │
执行调度器 ─────── Storage 与内存预算
    │                    │
    └────── Worker ───────┘
               │
          ITK-Wasm 计算
               │
       选定页或区域的原精度结果
               │
       二维 Canvas 视口与 UI 叠加层
```

Dataset 描述数据的含义与来源。Storage 决定像素在哪里，以及能够按什么范围读取。执行调度器把操作记录、用户当前页和内存预算转成具体任务。ITK Adapter 为一次任务构造计算所需的图像，视口根据相机从当前帧原始缓冲读取显示颜色。

ITK 的图像是 I/O 或计算期间的工作对象，视口读取产品自有 ImageBlock。整个 Dataset 的来源、版本、生命周期和区域读取能力由产品管理。ITK 与产品数组之间的复制仍需要按实际路径测量，不能视为全通路零拷贝。

第一版只建设文件来源、受预算约束的内存缓存、线性步骤链和一个计算后端。OpenCV、自定义 C/C++ 算子、Zarr、远程存储与多输入计算图通过后续需求引入。

## 3 Dataset 数据模型

Dataset 的模型借鉴 ITK 的科学图像语义，同时表达时间、通道和存储布局。

| 字段 | 含义与约束 |
| --- | --- |
| id 与 revision | 稳定的数据身份与内容版本，用于任务、缓存和结果追溯 |
| dtype | 首期覆盖 uint8、uint16、int16、float32；其他类型按实际格式与算法需求增加 |
| axes 与 shape | 有名字和语义的轴及长度，两者顺序必须一致；通常按 T、C、Z、Y、X 组织 |
| spatialTransform | 空间轴的 spacing、origin、direction 与单位；明确矩阵中的轴顺序 |
| timeCalibration | 时间单位、时间间隔或各帧时间戳，与空间变换分别表达 |
| channels | 通道名称、波长及科学语义；荧光通道与 RGB 分量明确区分 |
| source 与 storage | 原始文件身份、格式、页索引及存储引用；不强制持有完整像素数组 |
| metadata | 格式元信息和影响解释、计算或导出的必要属性 |

有些数据只有二维空间轴；有些 Stack 的页表示时间而不是 Z 深度。缺失的标定必须明确标为未知，不能自动假定每页相隔 1 微米。非均匀 Z 间距或逐页不同方向需要保留实际信息，不能错误套用统一空间变换。

计算缓冲还要明确内存布局、步长、分量数和所属区域。Dataset 的逻辑轴顺序与文件的实际布局可以不同，Adapter 负责转换并报告是否产生拷贝。

LUT、显示范围、当前 T/C/Z、缩放、平移、当前工具与选中步骤属于 ViewState，独立于 Dataset。修改显示状态不会修改像素，也不会被当作科学计算写入源数据。

命名轴和标定可参考 OME-Zarr。其规范约束轴与数组维度顺序，并为分辨率层定义坐标变换；格式适配时仍需检查能否表达 Dataset 的全部标定信息，尤其不能默认任意方向矩阵均可直接写入当前规范。[OME-Zarr 0.5 规范](https://ngff.openmicroscopy.org/0.5/index.html)

## 4 Storage 与区域读取

Storage 以读取指定页或区域为主要接口，并提供元信息、能力查询和资源释放。第一版的文件来源保留原始 File/Blob，内存只缓存正在使用或即将使用的数据。后续增加磁盘派生缓存、Zarr 或远程来源时不改变 Dataset 的科学语义。

TIFF 导入先建立 IFD、页及条带或瓦片的索引。优先按偏移读取所需字节，避免大文件一开始就调用完整 file.arrayBuffer。具体能否只解码一个区域取决于文件组织、压缩方式和解码器能力，必须实际验证。ITK-Wasm 的通用读图接口也不能直接当作已经具备按页随机读取能力的接口。

源数据保持只读。处理结果写入派生缓存或新的导出目标，不覆盖原始文件。源文件引用必须在会话内持续可读；刷新恢复、长期授权与源文件重新定位属于后续持久化功能。

块大小由读取布局、算法邻域与内存预算决定。局部滤波读取输出块周围的必要邻域，计算后只保留有效输出区域。只有图像真实边缘才使用规定的边界处理，块接缝不得被误当成图像边缘。

## 5 Stack 翻页与任务优先级

导入后首先准备当前页并显示原分辨率数据。随后在后台准备附近页面，预取范围受字节预算限制，并随翻页方向调整。预取包括解码以及当前步骤版本的计算，避免进入新页后才执行完整处理链。

| 优先级 | 工作 |
| --- | --- |
| 最高 | 当前目标页、当前 ROI 和像素探查所需数据 |
| 较高 | 翻页方向上的下一页及附近页面 |
| 普通 | 反方向邻页及短期可能访问的结果 |
| 后台 | 整组统计、批量导出及其他长任务 |

快速连续操作合并为最新目标，淘汰尚未执行的过时任务。旧任务完成后检查 Dataset、步骤和请求版本；过期结果不能覆盖当前画面。双向翻页和远距离跳页分别测量，不能用已经缓存的页代表所有翻页体验。

像素与页码作为一次显示提交一起更新。当前目标页未完成时可以保留上一帧，但必须显示实际正在展示的页与待加载目标，保证探查值、ROI 和页码不串页。

为避免长计算阻塞读页任务，解码与计算的队列和 Worker 资源需要有明确调度。Worker 数量按吞吐与内存实测确定，不能按 CPU 核数直接复制整套大缓冲。整组分析必须给当前浏览留出资源。

原分辨率翻页速度受读取、解码、计算和 GPU 上传吞吐共同限制。预取不能使无限制快速跳页都瞬时完成；原型阶段必须测清边界，不以低分辨率替换掩盖等待。

## 6 计算与算子约定

ITK-Wasm 按需求提供所选滤波、形态学、分割、统计和多维算子。注册表对 UI 暴露参数、数据类型、输出含义和作用范围，同时对调度器暴露执行与内存要求。

| 算子约定 | 必须声明的内容 |
| --- | --- |
| 输入与输出 | 支持的 dtype、维度、通道语义、输出类型和尺寸变化 |
| 参数与单位 | 参数范围、默认值、像素单位或物理单位，非法参数处理 |
| 作用范围 | 当前页、指定页段、整个 Stack、ROI；二维逐页与三维邻域计算明确区分 |
| 区域依赖 | 有限邻域及其大小、可合并统计、多遍执行或必须处理完整区域 |
| 数值规则 | 内部计算精度、输出舍入、截断或饱和、边界、NaN/Inf 和标签规则 |
| 资源 | 临时内存估算、并行方式、取消检查位置及算法版本 |

局部卷积与部分形态学可使用重叠块。统计可逐块累加再合并；ITK StatisticsImageFilter 本身支持分段输入和统计合并。[ITK 统计滤镜文档](https://docs.itk.org/projects/doxygen/en/stable/classitk_1_1StatisticsImageFilter.html)

连通域需要保留跨块连通关系并合并标签，不能独立标记后简单拼接。全局 FFT、配准或其他全局算法按具体实现规划工作区域；无法满足内存预算时应提前说明限制，不自动改变分辨率或算法定义。

高斯滤波需要区分有限核与递归实现。ITK 的递归高斯使用 IIR 方法，分块时不能默认有限 halo 足以得到完整图像上的同一结果。[ITK 递归高斯文档](https://docs.itk.org/projects/doxygen/en/stable/classitk_1_1SmoothingRecursiveGaussianImageFilter.html)

数据进入 WASM 后尽量在同一内存中执行一组步骤，复用允许复用的工作缓冲。算法内部确有需要的临时图像要计入预算；不承诺每次算法只有一次输出分配。不得通过每像素 JS 回调执行热点运算。

第一版用普通版与标准 SIMD 构建验证正确性和速度。浮点算法不默认开启改变数值语义的激进优化。多线程作为后续实测选择；若采用 Emscripten pthreads，部署需满足共享内存的隔离要求。[Emscripten SIMD](https://emscripten.org/docs/porting/simd.html)、[线程文档](https://emscripten.org/docs/porting/pthreads.html)

请求合并与真正中断是不同能力。同步 WASM 调用执行期间，所在 Worker 不能靠接收普通取消消息立即停止。首期在步骤或区域任务之间检查过期版本；需要更细粒度中断时必须为算法增加返回点或可见的取消标记，再验证实现。

## 7 操作记录与撤销

Recipe 保存源 Dataset 引用、步骤列表、每步的算子与参数、作用范围和版本。第一版使用线性链，至少记录最近一次提交前的 Recipe 状态。参数拖动作为临时编辑，提交后形成一次撤销单位，避免每次滑块事件都生成历史。

撤销恢复上一版 Recipe。当前页从只读源数据执行到对应步骤；缓存中恰好存在该版本结果时直接复用，否则重算。邻页随后按恢复的 Recipe 预取。撤销的元数据变更很快，但全分辨率画面恢复时间包含重算，不能保证通用的立即恢复。

缓存只保存少量页或区域的最终结果，不要求保存每步完整输出。点选某一步查看其结果时，从源数据执行到选定步骤；是否命中缓存不会改变功能正确性。选择中间步骤是查看行为，不自动删除后续步骤。

统计和表格是分析产物，不替代流向下一步的图像。结果需要注明输入 Dataset、Recipe、页或区域，以及计算是否已完成。某步失败时停止受影响的后续计算，标出失败原因；若显示最后一个有效步骤，必须明确其步骤身份，不能将其当作最终成功结果。

重算依赖完整的操作定义：算法版本、边界与舍入规则、ROI、连接性、标定、随机种子及影响结果的其他参数。算法升级不能悄悄改变旧记录的含义。未来局部画笔修改可用局部块差异记录，但这是单独的编辑能力，不作为第一版基础滤镜的撤销机制。

## 8 二维视口与原像素显示

二维视口仅创建与屏幕区域及 devicePixelRatio 对应的 Canvas。翻页更新当前 ImageBlock，相机驱动采样与叠加层，不创建源图尺寸的 Canvas。三维视口是后续独立功能，尚未选定显示后端。

视口只读取当前页缓冲。二维翻页不得为了显示就创建数百页原分辨率的 GPU 纹理或整图 RGBA 副本。

最近邻采样用于选取原像素显示，不混合相邻像素；窗宽窗位与颜色映射只改变屏幕颜色。显示缓冲和科学数据缓冲分离。

| 显示行为 | 规定 |
| --- | --- |
| 1 比 1 查看 | 一个图像像素对应一个屏幕物理像素，明确处理 devicePixelRatio 与像素中心 |
| 放大 | 同一个原像素显示为更大的方块，禁用平滑取样 |
| 缩小 | 最近邻选择原像素；视口说明缩小显示不包含全部像素，精确检查使用 1 比 1 或更大倍率 |
| 显示值 | 源图模式探查源数据；结果模式探查所选步骤的数据；两者都在 LUT 映射之前读取 |
| 科学精度 | CPU/WASM 的科学数组保留 dtype；显示过程中不得反向写回降精度或映射后的值 |
| 浮点显示 | 采样原始浮点数组，再映射屏幕颜色；不将显示用的 8 位颜色写回数据 |

UI 绘制 ROI、标尺、文字与手柄。ROI 保存图像索引坐标，测量的长期目标是通过空间标定换算物理量。UI 与视口共用坐标转换，并统一处理像素中心、Y 方向、边界和屏幕缩放；当前统计仍以像素面积为单位。

相机是视图变换的唯一执行者，滚动条与工具操作通过适配层驱动相机，叠加层读取同一状态。相机缩放和平移不得触发 ITK 重算。原始数值探查不得从截屏或 RGBA 颜色反推。

## 9 内存预算与所有权

内存规模按实际数据类型估算。以单页 4096 × 4096 为例：

| 像素类型或显示缓冲 | 一页 | 100 页 | 300 页 |
| --- | --- | --- | --- |
| uint8 单通道 | 16 MiB | 1.5625 GiB | 4.6875 GiB |
| uint16 单通道 | 32 MiB | 3.125 GiB | 9.375 GiB |
| float32 单通道 | 64 MiB | 6.25 GiB | 18.75 GiB |
| RGBA 8 位显示缓冲 | 64 MiB | 6.25 GiB | 18.75 GiB |

表格不含文件压缩、解码临时区、WASM 工作缓冲和 GPU 额外副本。这也是不能按每一步保存整个 Stack 的原因。

预算必须覆盖已解码源页、派生结果、解码临时区、WASM 已分配内存、显示副本和估算的 GPU 资源。已存在于 WASM 内存内的缓冲不再重复记账，但释放其中对象也不等于 WASM 已提交内存立即缩小。GPU 占用通常只能估算，应与实测一起报告。

先为当前页、一次任务的工作缓冲和当前显示预留空间，剩余预算才用于邻页缓存。按字节决定页数；同一个预算能容纳的 uint8、uint16 和 float32 页数不同。活跃数据在使用期间固定，其他页按距离、访问方向和最近访问顺序淘汰，防止全缓存固定后无法执行下一任务。

缓存键至少包含源版本、步骤版本、T/C/Z 或区域、输出类型和算法版本。转移 ArrayBuffer 会使发送侧失去该缓冲，不能一边转移一边假定原缓存仍可读取。必须为计算、显示和探查明确所有者、只读使用者与释放时机；需要显示副本时计入预算，不宣称端到端零拷贝。

256 MiB 可以作为第一轮受限内存测试配置，不是已拍板的产品默认值或所有机器的安全总上限。默认预算、可调整范围和最大单任务工作集由原型测量确定。既有 4000 万像素与 16k 边长限制仅作为旧实现参考；新引擎分别检查解码、算子和实际 GPU 能力，不能用单一限制代替这些检查。

## 10 当前代码与迁移范围

2026-10-01 查看图像工作树时，HEAD 为 6c20d65，stride 内核已提交。现有 processor、filters、binary 和 tiff 保留为参考实现与迁移测试来源；它们不能代表 16 位、多维数据或新引擎已完成。

ImageJApp 正在改为 UI 外壳，使用步骤面板、mock 注册表与 engineTypes 接口草稿。当前句柄仍主要描述二维宽高与 rgb/gray，导入与画布存在临时实现，计算结果尚未正式接入。这些是接缝草稿，不是最终的数据契约，现有 README 也主要记录旧实现。

后续需补齐 dtype、命名轴、标定、区域、版本、任务状态、分析产物与释放协议。Dataset、Storage、计算 Adapter 与渲染 Adapter 各自管理职责，不把这些能力全部隐藏在只有 importFile 和 run 的一个对象内。

本文新增文档不代表上述代码已修改、通过类型检查或达到性能目标。实际实现阶段按仓库 AGENTS 与对应 Next.js 指南执行。

## 11 分阶段实施与验收

| 阶段 | 交付物 | 出口条件 |
| --- | --- | --- |
| P0 数据契约 | Dataset、ViewState、Recipe、Storage 区域接口、所有权和算子能力约定 | 小型 uint8/uint16/int16/float32 数据的轴、原值、空间标定与区域读取正确 |
| P1 原型通路 | 真实科学 TIFF 单页读取、ITK-Wasm 代表算子、二维原值采样视口 | 无隐式 8 位转换；原值探查、最近邻显示、像素对齐与原尺寸结果正确 |
| P2 Stack 浏览 | 原分辨率邻页预取、队列优先级、有限缓存、过期结果处理 | 百页连续翻阅实测；双向、远跳、长任务并行时不串页，驻留内存随预算受控 |
| P3 步骤与撤销 | 参数提交、页或 Stack 作用范围、步骤查看、撤销最近一次提交 | 淘汰缓存后仍能撤销并得到相同结果；分析步骤不截断图像流；失败状态明确 |
| P4 算法扩展 | 所需形态学、标签、统计、三维算法与批量导出 | 每类算法验证边界、区域依赖、数值精度、内存与整图参考一致性 |
| 后续 | 磁盘派生缓存、刷新恢复、OME-Zarr、远程计算、按需线程或其他后端 | 由明确需求与测量结果决定，不作为第一版完成条件 |

三维数据展示的原型可提前验证，但不能阻塞二维科学查看与百页翻阅的主路径。

## 12 正确性与性能测量

正确性样例覆盖常量、阶跃、边界、单像素、小尺寸、各 dtype 极值、浮点特殊值、多通道、ROI、非单位标定和跨块接缝。显示验证使用像素棋盘、已知值图像、不同 DPR 和多倍率，并检查 LUT 调整后测量值保持不变。

迁移 ImageJ 算子时用明确版本的 Java 实现或已核实参考生成期望结果，记录阈值、连接性、边界、舍入和标准差等定义。已有 TS 内核提供对照，但不自动证明 ITK 默认配置与 ImageJ 逐像素一致。浮点算法根据定义采用逐值或误差容限验证，记录内部与输出精度。

性能样例至少包含 100 页与 300 页、4096 × 4096 的 uint16 数据，并使用实际的无压缩和压缩科学文件。合成数据按页生成，测试本身不能为了准备样例先把整个 Stack 放入 RAM。

| 测量项目 | 测量与验收方式 |
| --- | --- |
| 导入 | 分别记录索引建立、当前页解码、首张原分辨率结果显示时间 |
| 翻页 | 分别报告预取命中、冷页、双向翻页和远距离跳页的 p50/p95，以及稳定连续翻页吞吐 |
| 计算 | 分别记录读取、解码、WASM 数据交换、各算子、显示映射与 GPU 上传时间 |
| 撤销 | 区分元数据恢复与完整结果显示，记录缓存命中和重算路径 |
| 响应 | 记录主线程长任务和交互帧时间；整组统计或导出期间单独验证浏览响应 |
| 内存 | 报告缓存字节、WASM 已分配内存、临时缓冲、显示与 GPU 估算、淘汰后的平台期 |

第一轮提议以预取命中后的翻页首帧 p95 不超过 50 ms 作为目标，在固定机器、浏览器、数据和预算下验证后再确定产品门槛。冷页和高成本处理分别报告实测，不承诺统一 30 ms 撤销或 300 ms 大文件导入。

测试记录必须包含设备、浏览器、构建、数据类型、页数、压缩、算子、预热与缓存状态。每期先证明科学结果正确，再证明内存受控，最后根据实测决定 SIMD、线程、解码器或数据通路优化。

## 13 首期需要实测确定的参数

尚需实测和完善的内容包括目标设备与实际文件样例、压缩 TIFF 的指定页读取能力、ITK-Wasm 数据复制与临时内存、视口采样耗时、默认预算、邻页范围、Worker 数量和显示延迟门槛。

原型应围绕同一条完整链验证这些参数：读取指定页，执行一个滤波和一个分割或统计操作，显示原分辨率结果，连续翻页，撤销一次提交。该链完成后再扩展更多算法，避免只有接口与面板而没有完整可测的执行路径。
